# Torsion Integrator Budget v0.1

Status: ARCHITECTURE_CANDIDATE / NUMERIC_RISK_GATE
Epistemic operator: CHYBA
Canon promotion: explicit authority only

## Purpose

This gate bounds computational work generated by admitted mixed rational `m:n` resonance edges before QHTRI Kuramoto torsion integration. It preserves the existing Euler/Lipschitz stability contract and prevents a formally valid high-order rational edge from consuming an unbounded number of phase substeps inside one scheduler interval.

## Existing stability quantity

For canonical torsion edge `e=(i,j,m,n,tau,K,R)`:

```text
g_e = K*R
L_bound = sum_e g_e*(m_e^2+n_e^2)
dt_safe = 0.2/L_bound        when L_bound > 0
```

For target execution horizon `T_exec`, define the deterministic required substep count:

```text
N_sub = ceil(T_exec * L_bound / 0.2)
```

No integration starts before this quantity is computed from the complete admitted graph generation.

## Default v0.1 execution horizon

For identity-coupled live memory the first reference horizon is one base BioOS tick:

```text
T_exec = T0 = 100/783 s
```

The budget remains a separately versioned policy parameter. Changing the maximum allowed substep count requires a new policy receipt; runtime load must never silently relax it.

## Risk demonstrated by current Stage-2 ratio bounds

The current harmonic estimator admits reduced `p:q` candidates satisfying:

```text
1 <= q <= 16
1/4 <= p/q <= 4
```

This produces 301 reduced candidate ratios before the sampling/Nyquist gate.

Composing two admitted ratios can produce much larger reduced edge integers. A maximal integer-square load found under the declared ratio box is:

```text
(59/15) / (63/16) = 944/945
m^2+n^2 = 1,784,161
```

With the current maximum single-edge degree policy case `K=kappa`, `R=1`:

```text
kappa = ln(2)/(24*pi) = 0.009193150006360484
L_edge = kappa * 1,784,161 = 16402.059708498127
dt_safe = 0.2/L_edge = 0.00001219359053402161 s
N_sub(T0) = 10,474
```

Therefore ratio admissibility is not sufficient evidence of bounded live execution cost.

## Density is not the primary risk

For a complete 36-node canonical graph with 630 edges and all edges 1:1, the degree-max coupling policy gives each edge at most `kappa/35` and therefore:

```text
L_bound <= 630*(kappa/35)*2 = 36*kappa
        = 0.3309534002289774

dt_safe >= 0.604314468080058 s
```

This exceeds one base tick `T0`. High rational order, rather than graph density alone, is the critical budget variable.

## Admission policy

A graph generation must provide:

```text
MEMORY_EPOCH
EDGE_COUNT
L_BOUND
T_EXEC
N_SUB_REQUIRED
SUBSTEP_BUDGET
BUDGET_POLICY_ID
```

Reference v0.1 behavior:

```text
N_sub <= SUBSTEP_BUDGET -> INTEGRATION_BUDGET_PASS
N_sub >  SUBSTEP_BUDGET -> INTEGRATION_BUDGET_EXCEEDED
```

On budget exceed:

```text
INTEGRATION_BUDGET_EXCEEDED
 -> do not enter live phase step
 -> preserve source graph and evidence
 -> mark offending graph/edge set as computationally inactive for this policy
 -> scheduler may place later bounded analysis in a slower lane
 -> no automatic promotion to a faster lane
```

No edge is silently renormalized, truncated, replaced, or assigned guessed `m:n` values in order to force a pass.

## Optional deterministic diagnostics

The gate may additionally rank cost contribution:

```text
cost_e = g_e*(m_e^2+n_e^2)
share_e = cost_e/L_bound
```

This is diagnostic evidence only. Removing or transforming an edge requires a separately admitted graph-generation decision.

## Fail-closed conditions

```text
NONFINITE_L_BOUND       -> REJECT
NEGATIVE_L_BOUND        -> REJECT
NONPOSITIVE_T_EXEC      -> REJECT
SUBSTEP_BUDGET_MISSING  -> QUIET
MEMORY_EPOCH_MISMATCH   -> STALE_MEMORY_EPOCH
N_SUB_OVERFLOW          -> REJECT
BUDGET_EXCEEDED         -> INTEGRATION_INACTIVE
```

## Authority boundary

Passing this gate means only that the declared graph fits the declared bounded numerical execution budget. It grants no PNCAP capability, semantic authority, epistemic promotion, PNStore commit, or AUX effect authority.
